## V. Experiment

### 1. Experimental Setup

**Table I**  
**Experimental Setup**

| Parameter               | Description / Value                                      |
|-------------------------|----------------------------------------------------------|
| Programming Language    | Python 3.12                                              |
| RAM                     | 32 GB Corsair DDR4 3200 MHz                              |
| Processor               | 11th Gen Intel Core i7-11700K @ 3.60 GHz                 |
| Storage                 | 1 TB Kingston NV3 SSD (Read: 6000 MB/s, Write: 4000 MB/s)|
| Operating System        | Debian 12                                                |

The experimental setup described in Table I corresponds to the author’s current local machine, which was used to conduct all experiments presented in this thesis. This configuration was selected for practical reasons (availability and stability) rather than as a strict requirement of the proposed solution.

It is important to emphasize that:

The proposed methods and software pipeline are not bound to this specific hardware.
Any modern machine capable of running Python 3.12 (or a compatible version) and the required libraries can reproduce the experiments, provided that sufficient memory and storage are available for the corresponding datasets and workloads.
The use of Debian 12 offers a stable Linux environment with reliable package management, but the implementation is portable and can be executed on other operating systems (e.g., other Linux distributions, Windows, or macOS) with minimal adjustments, mainly related to environment setup and dependency installation.

The selected hardware characteristics support:

Efficient in-memory processing of datasets through 32 GB RAM, reducing the need for disk-based operations in typical scenarios.
Parallel execution of tasks and model training using the Intel Core i7-11700K with multiple cores and threads.
Low-latency I/O via the NVMe SSD, which improves data loading, logging, and model checkpoint operations.
A consistent and reproducible environment enabled by a fixed OS and software stack across all experiments.
To ensure reproducibility and consistency, the following measures were applied:

All experiments were executed on the same machine with the configuration shown in Table I.

Virtual environments (e.g., venv) were used to manage Python dependencies, with explicit version pinning (e.g., via requirements.txt) to guarantee consistent software behavior.
The same random seeds, data splits, and configuration files were used for all experimental runs.
While performance metrics such as execution time or resource utilization may vary on different hardware, the functional behavior, algorithmic results, and relative comparisons between methods are expected to remain valid when the experiments are replicated on other compatible systems.

In the following subsections, the datasets, evaluation metrics, and experimental procedure are detailed to further support reproducibility and to clarify how the results were obtained, independent of the underlying hardware platform.
